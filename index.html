A plain-language refresher · the overview before the detail

From fitting to
evidence

A model learns from examples. We compare it fairly, choose a measure that fits the job, and keep some examples aside to check how it handles cases it has not seen. That last check is evidence of performance—not a promise about every future case.

LMS lesson anchorsIndependent enrichmentInvented teaching data

The whole topic in one sentence

Fit means learn from the training examples; validation or cross-validation helps choose between approaches; a test set gives one final check; and a metric summarises a particular kind of success or error. Generalise means the model still works on cases it has not seen.

01Whole route
LMS anchor

Model building is a loop; the final check stays separate

The model is not judged by how well it handles examples it has already learned from. We need examples that did not teach it. During development, we can compare ideas using validation data. After we settle those choices, the test set gives a cleaner final estimate.

Why protect the test set? If we keep changing the model because of its test score, we have let that test set influence our choices. It no longer acts like an independent final check. A suitable split also depends on the data: dates, people, or repeated measurements may need to stay together or keep their order.

02What fit does
LMS anchor

Fitting connects available clues to known answers

Imagine a shop that wants to estimate daily revenue from the day's temperature. The input clues are written as X. The known answer for each past day is y. Fitting uses those pairs to create a model; prediction supplies clues for a new day and asks for an estimate.

Fit, then predict

fit(X_train, y_train) learns from known pairs. predict(X_new) returns an estimate—here, one simple illustrative straight-line estimate would be €170.

Plain meaning: the model is a learned recipe that connects input clues to an answer. fit is the learning step. predict uses that fitted recipe. In this toy example, temperature is the only clue; real revenue depends on much more than temperature, so the tidy pattern is only for showing the mechanism.

Keep separate

In supervised learning, the answer column is known for past examples. For a new example, the answer is the thing we want the model to estimate. Inputs and answer must stay aligned to the same rows.

Where GridSearchCV fits

A hyperparameter is a setting chosen before fitting, such as maximum tree depth. Hyperparameter optimisation compares settings on development data. GridSearchCV tries the listed values using cross-validation and compares their averages. We still choose a suitable metric and search options.

The middle setting has the lowest mean error. A real search can try several parameters and combinations. Refit the chosen setup on all 12 development days, then check the 4 untouched test days once.

scikit-learn scorers use a “higher is better” convention, so errors use negated scorers such as neg_mean_squared_error and neg_root_mean_squared_error. With these scorers, cv_results_ contains negative scores; the least negative is best (see the metrics and scoring guide).

The setting

Hyperparameter

A human-chosen control that shapes the learning process. Examples include tree depth or the regularisation strength. It is different from the values the model learns while fitting.

The comparison process

Grid search + CV

Try a stated set of candidate values, evaluate them over the same folds, and compare the chosen score. The selected option still needs a protected final check.

04Read scores
LMS anchor

A score is useful only when you know what it rewards

Numbers, categories and groups need different scores. A metric summarises one kind of performance. A baseline is a simple reference result for the model to beat.

Score · R²Usually higher is better ↑

1 is a perfect fit; 0 matches a constant prediction of the average target; below 0 is worse than that baseline.

Error · MAE / MSE / RMSEUsually lower is better ↓

Zero means no measured error. Compare the same metric on the same target and evaluation data.

Number to estimate

Regression

MAE, MSE and RMSE summarise prediction misses. R² compares predictions with a simple average-value baseline. No score is a percentage of predictions that are “correct.”

Named group to choose

Classification

Accuracy counts overall correct predictions. Precision asks how often positive predictions are right; recall asks how many actual positive cases were found. F1 balances precision and recall. If a class is rare, accuracy alone can hide misses.

Groups to discover

Clustering

There may be no known correct labels to compare with. A silhouette score checks how close examples are to their own group compared with nearby groups. It is a diagnostic, not proof that the groups are meaningful.

Choose for the decision

What counts as a mistake?

For a missed fraud alert, recall may matter. For unnecessary manual reviews, precision may matter. For revenue estimates, the size of the miss matters. Ask what a bad prediction costs before choosing one headline metric.

05Fit and generalise
LMS anchor

The training score is not the whole story

Invented example: a regression model scores R² 0.92 on training data and 0.54 on test data. R² is not “percent correct”: 1 is perfect, 0 matches an average-target baseline, and negative values are worse. The positive test score beats that baseline. A large drop is a signal to investigate, rather than proof of overfitting; the sample, split or data conditions may differ.

Four related terms in everyday words

Bias is the error pattern that comes from assumptions that are too simple; variance is how much the learned result changes when the training sample changes. Too much bias can cause underfitting: missing useful structure. Too much variance can cause overfitting: following training quirks and performing worse on new cases.

The aim is not the lowest training error; it is dependable performance on relevant new cases.

06PCA
Independent enrichment

PCA changes the input map; it does not score the model

Principal Component Analysis (PCA) is an optional way to represent data with fewer combined measurements. It looks for directions that capture a large share of variation in the original features. You might use it when there are many inputs and want a smaller representation to explore or pass to another model.

Illustrative feature names only. The component axes mix original inputs; they are not the target answer and do not automatically mean something intuitive.

What it can help with

Reduce the number of input dimensions while retaining directions that explain much of the data's variation. This can make some high-dimensional patterns easier to handle or inspect.

What it does not do

PCA does not predict the target, choose the best task metric, or guarantee better results. A component that explains input variation is not necessarily the information most useful for the prediction.

Keep the check fair: learn the PCA transformation from the training portion of each split, then apply that learned transformation to its validation or test portion. Learning it from all rows first can leak information into the evaluation. A scikit-learn pipeline can keep this order inside cross-validation.

07Useful questions
A discussion checklist

Questions that keep a model conversation grounded

You do not need to name an algorithm first. Start with the decision, the data, and the kind of mistake that matters. These questions help turn a vague “is this model good?” into a useful conversation.

01 · The task

What answer are we trying to estimate: a number, a category, or a grouping?

02 · The evidence

Which examples teach the model, which guide choices, and which stay untouched for a final check?

03 · The score

What does this metric reward, what does it miss, and which real-world error matters most?

04 · The comparison

What simple baseline should a more complex model beat? Were candidates compared on the same folds?

05 · The settings

Which hyperparameters were tried, and how was the winning setting selected?

06 · The inputs

Would a transformation such as PCA help, and was it fitted only inside the training split?

07 · The gap

How do training and held-out scores compare? Is the difference stable or just one split?

08 · The use

Does the test data resemble future cases, and how will performance be watched after launch?

Quick recall

Does an R² score of 0.54 mean 54% of predictions are correct?

No. R² compares a regression model with a constant average-target baseline. It is not classification accuracy or a percent-correct score.

Does cross-validation replace the final test set?

No. Cross-validation helps compare choices on development data. A separate test set can provide the final check after those choices are fixed.

Does PCA tell us whether our model is good?

No. PCA transforms the input features. Evaluation metrics judge the model's results for a particular task.

Does a large train/test score gap prove overfitting?

It raises a concern, but it does not prove the cause. Check the data split, sample size, target, baseline, possible leakage, and whether test cases resemble the intended future use.
